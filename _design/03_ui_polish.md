# PortGuard 界面优化走查（2026-10-21 / v1.2.x）

本轮是**视觉层级与状态可信度**的走查，不改信息架构、不改业务流程、不动判定链。
基线：`_design/01_visual_direction.md`（视觉方向）、`_design/02_ux_spec.md`（交互规范）。
所有改动均落在 `gui/`，`core/` 与 `app/` 未触碰。

---

## 1. 视觉主题

「素白哨岗 Paper Watchtower」不变：白底 + 石墨字 + 单一靛蓝强调色，颜色只表达语义。
本轮只解决三件事：

1. **第一屏读不懂**：统计卡把「量」放在「是什么」之前，三张卡右侧整片空白。
2. **勾选不可信**：勾选态是纯色方块（工具条）与灰框深色像素勾（表格）两套视觉，
   用户看不出「这张表勾了哪些行」。
3. **最关键的健康态缺席**：Windows 防火墙是否真在过滤，只写在封禁页的一条警示里，
   而它是「已封禁」三个字成立的前提。

## 4. 组件规范

### 4.1 统计卡 `StatCard`

- 尺寸：`Expanding × 90`，内边距 18/14，行距 2。
- 结构：`圆点 + 标签`（上）→ `数值 + 单位`（下，单位底对齐）。
- 状态：数值与圆点同色（`set_color`）；计数为 0 时回落 `text_on_dark`，不染红
  （红色 0 是噪声，会稀释真正有数时的语义）。
- 用法：`StatCard("今日访问", "0", unit="次")`。

### 4.2 勾选框（两处，一套视觉）

| 场景 | 实现 | 尺寸 |
| --- | --- | --- |
| 工具条 / 对话框 | QSS `QCheckBox::indicator` | 16×16，圆角 3，选中填 `primary` + 白勾 |
| 表格勾选列 | `CheckMarkDelegate`（自绘） | 16×16，同一圆角与配色，绘制在单元格正中 |

- 白勾来源 `assets/check.png`（13×13），由 `tools/gen_ui_assets.py` 生成，可重复执行。
- 为什么必须落一个位图：QSS 不支持 SVG data URI，也画不了折线；item view 的勾选
  指示器由 delegate 用基础样式绘制，`QTableView::indicator` 不生效。
- 勾着却被禁用：保留勾形、底色降到 `border_strong`，变回空框会让人以为勾选丢了。

### 4.3 卡片与工具条

- `QFrame#panel`：白底、`1px border_light`、圆角 8。
- 卡片标题行：内边距 16/12/16/8，标题 `panel_title` 16/600 + 一句 `text_muted` 12.5。
- 卡片内工具栏：左右 16、行间距 8，与标题行同一条左基线。

### 4.4 分隔条 `QSplitter`

10px 透明手感区，悬停才显 `border` 色。1px 实线夹在两张白卡之间时会被读成表格边框。

## 5. 布局

- 页面外边距统一 24/16/24/12，控件间距 12，卡片内 16/8。
- **风险事件页**：`筛选行 + 批量行` 装进一张工具卡，中间 1px 分隔线 —— 两行性质不同
  （筛选是「看哪些」、批量是「改哪些」），但同属「对整张表做点什么」。
- **封禁管理页**：上下两块统一为卡片（`待确认的封禁建议（N）` / `封禁记录（N）`），
  各带标题行、筛选行、批量行；两块之间用 10px 透明分隔条。原来下方是裸工具栏 + 裸表格。
- **顶部状态条**：`防火墙 · 本机观察 · 权限`，顺序即「是否真在防护 → 在保护谁 → 能不能动手」。
- **表单内容列（2026-10-22）**：规则配置与设置页的卡片限宽 `CONTENT_MAX_W = 900` 并
  水平居中（`QVBoxLayout.setAlignment(AlignHCenter)`）。1360 窗口下页面可用宽约 1160，
  而这两页每行只有「128px 标签 + 一个字段」，铺满会把卡片拉到 1100 宽、内容只占左侧
  60%。900 的依据是实测最小需求：规则卡最宽一条（`geo_sensitive_port`，4 个参数）810，
  设置面板最宽一块（离线库在线同步）846，各留 50~90 余量。
  **不做两列卡片流**：`geo_sensitive_port` 一卡就要 810，两列 580 放不下，字段会溢出。
- **内容列只用于表单页**：监控 / 事件 / 封禁 / 历史访问是表格页，仍然满宽 —— 表格列宽
  预算是按 1099 视口算的，收窄反而更挤。

## 6. 层级与深度

无阴影（QSS 不支持）。分层只靠三档明度：页面 `#F4F6FA` → 卡片 `#FFF` → 表头/抬升面
`#F8FAFC`；1px 线只给可交互对象与卡片边界。

## 7. 注意事项（踩过的限制）

- QSS 只支持单值 `border-radius`，无 `box-shadow` / `transition` / `letter-spacing`。
- 图片资源必须用**绝对路径**进 QSS：快捷方式启动时工作目录不是程序目录，
  相对路径会静默失效（已走 `core.config.resource_path`，打包后指 `_MEIPASS`）。
- 勾选框不要图省事「只改底色」：浅色主题下纯色方块与禁用色块无法区分。
- 表格勾选列的命中判定交给基类（点指示器切换），自绘只负责画，不接管鼠标。

## 8. 尺寸与输入

- 窗口最小 1240×720，默认 1440×900；截图按 1360×860 复核。
- 表格列宽为硬约束（无横向滚动）：有界内容给足不截断，无界内容（路径 / 命中规则 /
  原因）走 tooltip。
- **列宽预算（2026-10-22 重算）**：1360 窗口下表格视口实测 **1099**（监控 / 事件）、
  **1097**（封禁记录）。每页只有一列是 `Stretch`，它拿到的是「视口 − 固定列合计」，
  所以改任何固定列都会直接改变这一列的宽：
  | 页 | Stretch 列 | 固定列合计 | Stretch 实得 | 该列内容需要 |
  | --- | --- | --- | --- | --- |
  | 实时监控 | 请求 | 890 | **209** | 205（`POST /api/v1/orders/search`） |
  | 风险事件 | 路径 | 977 | 122 | 110（`/api/v1/orders/search`，不含方法） |
  | 封禁记录 | 原因 | 829 | 268 | 234（`[自动] 命中规则：判定风险：1024`） |
  旧监控配置固定列合计 1151 > 1099，请求列只剩 121 —— `POST /admin/login` 显示成
  `POST /admi…`，除右键菜单外看不出访问了什么。**加列 / 加宽前先算这张表。**
- **Qt 的单元格内边距比 QSS 写的 `padding: 0 10px` 更大**：处置列按 `QFontMetrics`
  量「仅提醒」= 40px、加 20 内边距 = 60，但 62 仍然渲染成「仅…」，70 才稳。
  所以短词列的定法是「实测 + 10」，不能只用字宽 + 内边距。
- 所有图标按钮 22×22（行内）/ 30×30（工具条），表格行高 34，表头 44（比行高更高，
  算建议卡高度时必须按 44 算，别用 34）。

## 10. 第二轮（2026-10-22）：把「留白 / 截断 / 没反应」收口

第一轮解决的是层级（卡片、勾选、状态），第二轮解决的是**预算与反馈**：三处内容
排不满、两处列宽超出了表格可视区、一处点了刷新没有任何回应。这一轮全部改动都在
`gui/`，`core/` 一行没动。

### 10.1 监控表列宽重排（按实测，不按感觉）

`_design/measure_cols.py` 的思路：把每列最长内容用 `QFontMetrics` 量出来，加内边距
后与列宽逐列比对，输出「需 / 现宽 / 余」。改前结果：

```
请求  宽=121 需=205 截断  'POST /api/v1/orders/search'
服务器 宽=92  需=108 截断  'web-prod-01'
```

重排后（固定列 890，请求列 209）：

```
时间 72 · 风险 52 · 来源 IP 138 · 归属地 132 · 端口 58 · 协议 52
请求 209(Stretch) · 状态 52 · 命中规则 152 · 处置 70 · 服务器 112
```

三处刻意的取舍：

- **归属地只给 132**：境内「河南省 洛阳市」108 够用，境外「加利福尼亚州 弗里蒙特」
  要 164，超出后走 tooltip —— 用 32px 换请求列能完整显示路径，划算。
- **处置 70 而不是 60**：`QFontMetrics` 说 60 够，实际 62 仍渲染成「仅…」，见 §8。
- **来源列 58 而不是 50**（封禁记录）：「自动」在 50 下被渲染成「自…」，同一类偏差。

### 10.2 事件页：计数行挪位 + 操作列加宽

`共 66 条事件（同类合并为 3 组） · 更新于 08:18:33` 原本挂在筛选行末尾，而那一行
已经有搜索框 + 4 个下拉 + 复选，1360 下直接溢出卡片右边被裁。挪到批量行右端（那
一行只有按钮、右半本来就空着），并把操作列 96 → 106（行内「封禁」+「⋯」两个按钮
在 96 下第二个被切掉）。

### 10.3 建议卡高度吸附整数行

`QSplitter` 给的 268 不是「面板开销 + N×行高」：表头 44 + 卡头 46 + 边 4 = 94，
268 − 94 = 174 = 5×34 + 4 —— 底部正好露出 4px 的下一行，看着像半行被切掉。

做法不是写死 264/298，而是在 `showEvent` 与 `splitterMoved` 后按**实测开销**吸附：

```python
rows   = round((panel.height() - chrome) / row_height)
target = chrome + rows * row_height      # chrome = 卡头 + 表头 + 边框，运行时量
```

不写死 94 的原因：卡头高度随字体走，两栈（雅黑 9pt / PySide2 度量偏大）差两三个
像素就会让吸附算错一行。

### 10.4 卡头抗压：说明是唯一可牺牲项

卡头一行装「标题 + 说明 + 已选 + 4 个按钮」，`sizeHint` 合计 655。说明
（「规则引擎建议，需人工确认」）与页头副标题重复，所以把它设成
`QSizePolicy.Ignored`（布局优先压它）+ 页面宽 < 900 时直接隐藏。
**按钮是操作入口、说明是补充信息** —— 挤压时先牺牲后者。

### 10.5 刷新中间态：`RefreshGuard`

原实现点了「刷新」没有任何回应，用户只能用「表格内容变没变」猜有没有生效。
新增 `widgets.RefreshGuard`（上下文管理器），四个列表页共用：

| 阶段 | 标签文案 |
| --- | --- |
| 进入 | `正在刷新…`（并 `processEvents()` 一次，否则字画不出来） |
| 结束 | 页面写的结果文案 + ` · 更新于 HH:MM:SS`；页面没写就只留时间戳 |
| 异常 | 照常向上抛（吞掉会变成「界面没反应」，更难查） |

`processEvents()` 期间界面仍会收点击，所以进入前先查 `busy` —— 叠两次查询不只是
浪费，列表还会被两次重排。三个列表页的 `refresh()` 都改成「先查 busy → with 包住
整个查询与渲染」。

**没做遮罩**：本机 SQLite 查询 10~50ms，灰蒙一层只会闪一下，比不提示更像卡顿。

### 10.6 IP 查询页

- 单条查询结果从「一句拼起来的长文本」改成**四个固定字段**（归属地 / 国家码 / ISP /
  范围），2:1:1:1 分宽。原文案字段边界全靠全角空格，长 IPv6 归属地一超宽整句换行。
- 库信息从 `PageHeader` 的 action 区挪到标题下独立一行 —— 和标题、按钮抢同一条
  横向空间时被压成半截话。
- 初始就调 `_toggle_empty()`：原先表头与空态同时出现，页面下半悬着一块只有表头的
  空表格。

### 10.7 `EmptyState` 折行

自动换行的 `QLabel` 在 `QVBoxLayout` 里只拿「最小宽度」，说明会被折成
「输入 IP 后点查询，结 / 果会显示在这里」这种断在词中间的碎句。改成
`setMinimumWidth(320) / setMaximumWidth(460)` + 水平居中，先按整句排、超 460 再换行。
四个页面的空态一起受益。

### 10.9 剩余 / 下一轮候选

1. **设置页下半部空**：「服务与采集」tab 只有一个面板，页面下方 400px 空白。这是

2. **规则卡内字段靠左**：卡片 900 宽，`geo_sensitive_port` 内容 810 尚可，但「黑名单

   视觉更乱，暂不采用）。
3. **历史访问页「用户代理」列**：1360 下只显示成 `Mozilla/5.0 (…`，按设计属无界内容、
   走 tooltip，但如果要显示，需要把「状态码 / 评分」两列合并。
4. **刷新时间戳没有 hover 详情**：只能看到「几点刷的」，看不到「刷了多少行 / 耗时」。
