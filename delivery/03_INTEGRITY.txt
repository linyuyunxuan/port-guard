PortGuard · 完整性校验与发布者身份说明
================================================

本文件说明如何确认拿到的交付包未被改动，以及本版本在「发布者身份」
上的真实现状。企业安全评审、白名单申报与批量部署前请先读完。


一、压缩包完整性（部署前必做）
------------------------------------------------
  随压缩包一并提供的 PortGuard-v<版本>.zip.sha256 是整个压缩包的
  SHA256 校验单，内容为「<小写哈希>  <压缩包文件名>」。

  在 Windows 命令行中进入两个文件所在目录，执行：

      certutil -hashfile PortGuard-v<版本>.zip SHA256

  把输出中的哈希与 .sha256 文件内容比对（不区分大小写）。
  两者一致，才能确认压缩包在传输 / 分发过程中未被替换。
  certutil 是 Windows 自带工具，不需要额外安装任何软件。

  也可使用贵司既有的文件完整性校验流程；请勿仅凭文件名或邮件正文
  判断版本与来源。


二、解压后的逐文件核验
------------------------------------------------
  包内 SHA256SUMS.txt 列出除自身以外每个文件的 SHA256 与相对路径，
  可用于两类场景：

    · 批量分发后抽查某台机器上的文件是否被替换 / 损坏；
    · 安全评审中登记程序目录基线，后续比对是否出现未知文件。

  校验单由打包脚本在生成压缩包时自动计算，解压后请保持文件相对路径不变。


三、发布者身份现状（务必如实告知安全评审）
------------------------------------------------
  · 本交付版本的 PortGuard.exe **未进行 Authenticode 数字签名**，
    Windows 资源管理器可能显示「未知发布者」，SmartScreen 或企业应用
    白名单策略也可能提示或拦截。这不代表文件损坏。
  · 因此在取得签名版本之前，**请以第一节的随包 SHA256 校验单作为
    完整性依据**；需要「可验证发布者」的采购 / 等保场景，请向供应方
    索取带签名的版本，并在验收材料中登记签名主体与证书有效期。
  · 若贵司采用按哈希加白的终端策略，建议以校验通过的 exe 文件哈希
    建立条目，而不是仅按路径或文件名放行；每次升级后哈希都会变化，
    需同步更新白名单。
  · 压缩包外的 .sha256 文件请与压缩包通过不同通道或同一受控渠道一并
    提供给最终使用方，避免只发文件、不发校验单。


四、权限与信任边界
------------------------------------------------
  · 主程序声明为 asInvoker（默认普通权限 / 观察模式），不以管理员常驻。
    查看采集、风险、历史、统计与导出都不需要高权限，也不会写防火墙。
  · 只有封禁 / 解封、到期巡检删规则、防火墙日志与名单规则写入等动作
    需要管理员。入口只有两处且都由用户主动触发：随包的
    start-as-admin.bat，或封禁管理页的「以管理员身份重启」；两者都会
    弹一次 UAC 由操作员确认。程序不会在后台静默提权，也不会写计划任务
    或注册高权限服务；开机自启（默认关闭）只写当前用户的 HKCU Run 值，
    启动的是观察模式。
  · 若贵司安全策略要求「开机即以管理员运行」，请由管理员用
    start-as-admin.bat 自行配置启动项，不要用兼容性设置绕过 UAC。
  · 程序不开放监听端口，不含遥测上报；出站行为仅两类：默认关闭的
    Webhook（地址由管理员填写）与可关闭的离线库在线同步。
    详见 01_DEPLOY.txt 第五节、02_TERMS.txt 第三节。
  · 程序会创建名称以 PortGuard_Block_ / PortGuard_Allow_ 开头的
    防火墙入站规则。卸载时这些规则不会自动删除，请按 01_DEPLOY.txt
    第七节清理；否则会继续影响业务访问。
