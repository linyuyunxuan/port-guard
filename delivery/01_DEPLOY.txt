PortGuard · 部署 / 升级 / 卸载 / 故障自查
================================================


一、适用环境
------------------------------------------------
  · 64 位 Windows 7 SP1 / Windows Server 2008 R2 及以上（本交付包为
    Python 3.8 + PySide2 5.15.2.1 / Qt 5.15 线路）。
  · Windows 7 / Server 2008 R2 需已安装 KB2999226（或 VC++ 2015-2022
    可再发行组件）：该系统不自带 UCRT，缺少时程序无法启动。
  · VC++ 运行库已随包放在 _internal/ 内，无需另外预装。
  · 建议解压到不含中文与空格的固定目录（例如 C:\PortGuard\），
    不要放在临时目录、桌面或会被清理工具扫描的位置。
  · 本包无需安装、不写系统服务、不创建计划任务；开机自启（若开启）
    仅写入当前用户的「启动」注册表项。


二、权限要求与能力边界
------------------------------------------------
  · 主程序默认以**普通权限**启动（清单为 asInvoker），即只读 / 观察模式：
    实时监控、风险事件、历史访问、IP 查询、规则配置、统计、策略快照与
    审计导出都能正常使用；程序不会写 Windows 防火墙，也不弹 UAC。
  · 需要管理员的动作：确认封禁 / 解封、一键全部解封、到期自动删规则、
    开启防火墙安全日志与安全启用防火墙、名单规则写入。两种切换方式：
      ① 退出程序后双击随包的 start-as-admin.bat（会弹一次 UAC）；
      ② 在封禁管理页点「以管理员身份重启」（同样弹 UAC）。
    程序不会在后台静默提权；顶栏「权限」点开可随时查看完整能力边界。
  · 观察模式下有两处要如实告知：① 已到期但解不掉的防火墙规则仍在生效，
    封禁管理页会显示条数与原因；② 若页面出现红色「封禁状态读取失败」横幅，
    说明数据库没读到，列表里的「未封禁」不能作为判断依据，请点横幅上的
    「重试」或查看运行日志。
  · 开机自启默认关闭；开启后是普通权限观察模式，不弹 UAC、不写防火墙。
    若贵司要求「开机即以管理员运行」，请由管理员用 start-as-admin.bat
    自行配置启动项，程序不代为提权。
  · 程序不开放任何监听端口；所有网络行为均为出站，且可按第五节关闭。


三、首次部署
------------------------------------------------
  1. 校验压缩包（见 03_INTEGRITY.txt），解压到固定目录。
  2. 直接双击 PortGuard.exe（普通权限即可，不弹 UAC）。首次启动会建立
     用户数据目录，并把随包附带的离线 IP 库复制到该目录；需要执行封禁时
     再按第二节的两种方式切换到管理员模式。
  3. 在「关于」页核对程序版本，应与 VERSION.txt、压缩包文件名一致。
  4. 在「设置 → 数据与离线库」查看两个离线库（IPv4 / IPv6）的加载状态。
     本交付包已自带离线库，纯内网环境首次启动不需要联网即可查询归属地。
  5. 建议先观察一段时间，再决定是否启用自动封禁；默认只出建议、不自动封禁。
  6. 若需要程序随登录启动，请在设置页开启开机自启；该开关默认关闭，
     开启后每次登录都会弹出一次 UAC，请先评估无人值守场景是否可接受。


四、数据与配置位置（升级时必须保留）
------------------------------------------------
  程序目录内的 _internal/ 是只读资源，可以用新版本整体覆盖。
  所有运行期数据都写在：  %APPDATA%\PortGuard\

     port_guard.db          事件、封禁账本、审计记录与全部设置
     rules.json             自定义访问 / 评分规则
     blacklist.json / whitelist.json   黑白名单
     ip2region_v4.xdb / ip2region_v6.xdb   离线库运行副本
     xdb_manifest.json      离线库版本指纹
     logs\                  portguard.log 与按天归档（默认保留 30 天），
                            以及 diag-*.txt / crash-*.txt 诊断报告
     backup\                数据库与离线库备份
     download\              离线库下载临时目录

  升级时请完整保留该目录；删除它等于清空全部设置、审计记录与封禁账本。


五、纯内网 / 无外网出口的环境
------------------------------------------------
  · 离线 IP 库已随包附带，首启即可离线查询，不需要外网。
  · 但「离线库在线同步」默认开启，启动约 3 秒后会向白名单主机
    （api.github.com、jsDelivr CDN 等）发起出站 HTTPS 检查与下载。
    无出口的内网请在「设置 → 数据与离线库」关闭以下三项：
      自动同步（xdb_auto_sync）、启动时检查（xdb_sync_on_start）、
      自动下载（xdb_auto_download）
    也可按需使用同页的「立即同步 / 强制重新下载」在内网有临时出口时手动更新；
    若只是启动期没读到本机库文件，用同页「重新加载定位库」即可，
    该动作不联网、不重启。
  · 告警默认只在本地呈现（托盘气泡、提示音、风险事件页）。
    设置页「防护与告警」中可选启用外部推送（Webhook）：开启后会把风险
    事件的来源 IP、归属地、目标端口、评分、命中规则与处置结果，以文本形式
    POST 到由管理员自行填写的地址。该功能默认关闭且地址为空；启用前请
    自行确认目标地址与数据外发符合贵司合规要求。
  · 程序不会向任何内置地址回传数据，也没有遥测 / 使用统计上报。


六、升级步骤
------------------------------------------------
  1. 退出正在运行的 PortGuard（含托盘图标）。
  2. 备份整个 %APPDATA%\PortGuard\ 目录（至少含 port_guard.db 与 rules.json）。
  3. 校验新压缩包完整性，解压后用新的程序文件覆盖原程序目录。
     注意：是覆盖程序目录，不要删除 %APPDATA%\PortGuard\。
  4. 启动程序（普通权限即可），在「关于」页确认版本号，并对照
     04_CHANGELOG.txt 了解本版变更；需要继续封禁时再切到管理员模式。
  5. 复核关键设置、自定义规则与黑白名单是否保留，再恢复日常运行。
  6. 本版本不提供应用内自动升级。请按 VERSION.txt 与更新日志自行判断
     是否需要升级；版本查询方式见第八节。


七、卸载步骤（务必按顺序，否则会留下防火墙规则）
------------------------------------------------
  1. 退出程序（含托盘图标）。
  2. 在「封禁管理」页对仍在生效的封禁执行解封；若已无法进入程序，
     请由管理员在「高级安全 Windows 防火墙」中删除显示名以
       PortGuard_Block_   开头的入站阻止规则，以及以
       PortGuard_Allow_   开头的入站放行规则。
     这些规则不带系统级到期时间，程序不再运行时不会被自动清理；
     遗留的阻止规则可能继续影响业务访问。
  3. 在设置页关闭开机自启（会移除当前用户「启动」项中的 PortGuard 值）。
  4. 删除程序目录。
  5. 按需删除 %APPDATA%\PortGuard\：保留它便于日后重装沿用配置与审计记录，
     删除它则彻底清除本机数据。请先确认其中的日志与备份已按需归档。
  6. 本程序不写系统服务、不写计划任务、不在程序目录之外写入其它位置，
     因此完成以上步骤即可清理干净。


八、版本查询与故障自查
------------------------------------------------
  版本查询（四处应一致）：
    · 程序内「关于」页 / 侧栏底部版本号
    · 包内 VERSION.txt 与压缩包文件名
    · 右键 PortGuard.exe → 属性 → 详细信息 → 文件版本 / 产品版本
    · 运行日志首行「PortGuard <版本> 启动：运行方式=打包 exe 管理员=…」

  自诊断：
    · 在命令行执行 PortGuard.exe --diag --quiet：逐项探测运行环境、
      依赖闭包与权限，打印结果并写报告，退出码 0 表示环境检查通过；
      加 --quiet 不会弹出任何窗口，适合批量部署脚本调用。
    · 报告与日常日志都在 %APPDATA%\PortGuard\logs\ 下，
      文件名类似 diag-YYYYMMDD-HHMMSS.txt 与 portguard.log。

  常见现象与自助处理：
    · 归属地显示「未知」表示该地址在库里没收录（内网 / 保留段 / 未收录）；
      显示「读取失败」或状态栏写「定位库 读取失败」表示库没加载出来，
      请到「设置 → 数据与离线库」点「重新加载定位库」，必要时再用
      「立即同步 / 强制重新下载」。启动期加载失败不再弹窗阻塞，
      无人值守部署也不会卡住。离线库精度只到城市级别，不保证 100% 准确，
      不应作为行政或法律判断依据。
    · 页面顶部出现红色「封禁状态读取失败」横幅：说明封禁账本没读到，
      此刻列表中的「未封禁 / 可封禁」不可信。点横幅「重试」刷新，
      仍失败请按本节自诊断生成报告并连同运行日志提供给支持方。
    · 顶栏防火墙状态为「未知」：程序按固定周期轮询，可稍候；持续未知时
      用 --diag 生成报告并核对防火墙服务与权限。
    · 规则写入失败：界面会给出归因（例如防火墙 profile 全关、权限不足），
      完整堆栈写在运行日志中，请连同日志一并提供给支持方。
    · 需要确认「程序是否在跑」：查看运行日志的启动行，或看总览页的
      实时流状态条与风险事件计数。


九、批量交付提示
------------------------------------------------
  · 每台机器都要单独完成第三节的首次部署与第五节的内网设置；本版本
    不支持多机集中视图。但**逐台配置可以复制**：在「设置 → 数据与离线库 →
    策略快照」点「导出策略快照」，拿到目标机点「导入策略快照」即可带上
    规则配置、黑白名单与策略设置。快照不含事件 / 封禁账本 / 审计等运行数据，
    也不含 Webhook 地址、镜像代理等本机凭据；导入前自动备份、失败可回滚，
    备份在 %APPDATA%\PortGuard\backup\policy-* 下。
  · 「设置 → 操作审计」点「导出 CSV」可导出当前筛选条件下的全部审计记录
    （不受分页限制），额外带「主机名 / 程序版本」两列，便于多机汇总与合规归档。
  · 各机器版本可能不同，报障时请一并提供「关于」页版本号与运行日志，
    便于按版本定位。
  · 随包的 NOTICE.txt 与 licenses/ 是第三方组件许可材料，二次分发时
    请勿从包中移除。
